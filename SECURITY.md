# Security model and audit

Audit scope: the current application and migrations through `0010_security_audit.sql`. Local tests do not prove that an external Supabase project has applied these policies.

## Security model

Participants are untrusted: assume DevTools can edit clocks, component state, HTTP bodies, IDs, cookies and repeat requests. All active administrators manage the entire site; owner_id is attribution, not tenant isolation. Both profiles and admins must be active. Metadata and public signup cannot grant administration.

Admin middleware/layout requires verified Supabase Auth and membership, including demo mode. Every mutation/repository checks again; admin SQL RPCs also call is_admin(). Server actions use Next's Origin checks. Participant APIs use strict bounded JSON and exact configured Origin. Public RPC operations are fixed server code, never selected by caller-controlled operation names.

The service key and QUIZ_SESSION_SECRET stay in server-only modules. Do not put them in NEXT_PUBLIC variables. Admin document endpoints legitimately return answer keys only to administrators. No participant component receives those documents.

## RLS strategy

All application tables have RLS. Anonymous reads are limited to published marketing catalog and explicitly public settings. Hidden parent sections hide their courses. Quiz answer tables, attempts, sessions and old public quiz views are revoked from anon/authenticated/PUBLIC. The runtime entry point is executable only by service_role. Internal historical wrappers and grading/ranking functions are not callable by participants. SECURITY DEFINER functions use a fixed empty search_path and qualified names.

Admin report detail queries require both quiz_id and attempt_id. CSV export is admin-only and escapes spreadsheet formulas. Runtime checks token hash, quiz/slug, expiry and attempt.access_session_id together. The leaderboard returns only currently approved fields, never the full participant_data object.

Storage contains public marketing images only. Admin-only policies restrict writes; bucket MIME and size limits are a second check. The app decodes JPEG/PNG/WebP up to 5 MiB and 20 million pixels, rejects mismatched/animated files, strips metadata/trailing content by re-encoding to WebP. Trusted admins can still write directly through their Storage permissions; that is not a participant privilege. Archived/replaced images may remain accessible at their old public URLs.

## Grading trust boundary

Start locks the quiz, checks its current revision/state/schedule with database time, validates participant fields server-side, counts attempts under the same lock, and captures a private question snapshot. started_at and deadline are generated by PostgreSQL. Request UUID makes retries idempotent; existing active sessions resume their attempt.

Save/submit lock quiz then attempt, verify ownership and question membership, validate option values against the snapshot and never trust client score/time. Late requests cannot replace saved answers. Submit calculates correctness, points, total/max score, correct/wrong counts and submitted_at in one transaction. Duplicate submissions return the stored result. duration_ms equals floor((submitted_at-started_at) in milliseconds). Ranking is score DESC, duration_ms ASC, submitted_at ASC, then UUID.

Safe question DTOs contain only IDs, question content/type/points and options. Regression checks seed a unique private accepted answer and scan HTML, RSC, API responses, static JS and React props/state for leakage. Anon and authenticated non-admin SQL tests deny answer-bearing tables/views/functions. These are tests of exercised paths, not a formal proof or a live deployment audit.

Current migration 0009 removes public review entirely: answer keys/details are admin-only even after closure. This supersedes older README descriptions of answer review. The audit preserves that policy. Result block visibility is checked using DB time and owned submitted attempts. Admins can intentionally publish solution text/video in result blocks; no raw HTML is rendered.

## Sessions and rate limiting

Quiz passwords use salted scrypt (128-bit random salt, 64-byte key), strict hash format validation and timingSafeEqual. Plaintext is POST-only, not persisted or logged. Supabase Auth handles admin passwords.

Unlock generates a random 256-bit opaque HttpOnly cookie; only its SHA-256 hash is stored. Unknown caller-chosen tokens are replaced. Renewal reuses a token only when its existing session belongs to the same signed visitor and quiz. SQL also prevents cross-visitor/quiz rebinding. HTTPS uses Secure, SameSite=Strict and __Host- cookies without Domain. HTTP is accepted only for loopback development. Origin configuration is mandatory; request Host is not a fallback trust anchor. Admin SSR auth cookies are HttpOnly.

Unlock authorization lasts one hour, owned attempt access 30 days. Visitor cookies are HMAC-signed. Identity digests are keyed HMACs after Unicode NFKC/case/whitespace/numeric normalization. Keep the secret random and stable.

Shared PostgreSQL budgets: 8 unlocks/15 minutes per visitor+quiz, 60/15 minutes per quiz across visitors, 600/minute global; 240 runtime requests/minute per valid session; admin login 10/15 minutes per email digest and 120/minute global. Counters commit on denial. Admin login now also requires the server service key, session secret and migration 0010. Supabase's own Auth rate limits/CAPTCHA must remain enabled because its public Auth endpoint can be called directly. Shared budgets can be exhausted to deny service; use edge/WAF protection and tune for legitimate traffic.

## URLs, XSS and caching

Stored text is rendered by React, never dangerouslySetInnerHTML. YouTube URLs require exact supported host/path and 11-character video ID, and become youtube-nocookie HTTPS embeds. Iframes are sandboxed. External HTTP(S) links reject credentials, whitespace and backslashes; new tabs use noopener/noreferrer. Redirect destinations are fixed internal paths. No server URL-fetch proxy was introduced.

Responses include nosniff, no-referrer, DENY framing, disabled camera/microphone/geolocation and object/base/form/frame CSP restrictions. This CSP does not yet implement nonce-based script-src; safe rendering remains the primary XSS boundary. Admin/quiz pages and APIs are private/no-store.

## Fixes and evidence

This audit fixes chosen-token session fixation, renewal binding, cookie-reset brute-force budgets, missing runtime/admin-login throttling, demo admin-page bypass, image-signature-only validation, admin SSR cookie exposure to JS, credential-bearing catalog URLs, request-Origin fallback, iframe sandboxing and response security/cache headers. Migration 0010 additionally revokes PUBLIC table/view/helper-function and schema-create privileges.

Commands: npm run verify; npm run test:public-quiz; npm run test:result-builder; npm run test:cms-browser; npm run test:smoke. Browser tests use the production Next server and local PostgreSQL WASM HTTP fixtures. Unit/database tests cover authorization, IDOR, scoring, duration, deadlines, retry/duplicate submit, snapshots, stale versions, forged tokens, admin suspension, URL attacks, image polyglots, CSV formulas and result visibility. No secrets were committed.

## Known limitations

- No live Supabase credentials were available. Apply all migrations and test actual Auth/PostgREST/Storage, HTTPS and cookies on staging. PGlite serializes connections internally; true multi-connection PostgreSQL contention is not yet tested.
- A self-reported identifier is not verified identity. Without an identifier, quota is per browser cookie; changing cookies/devices changes identity. Auth/OTP is required for limits per real person. Someone can impersonate or exhaust another self-reported identifier.
- The app cannot prevent photographing questions, collaboration or score inference across attempts. Admins must choose release/attempt policies appropriately.
- No expiry background worker: abandoned attempts finalize on a later owned request/start. Unsaved offline answers are lost; actual submission duration includes reconnection delay. Answer acceptance cannot be extended by changing the timer.
- Leaderboard fields are an explicit administrator privacy decision. Third-party images/video can observe client IPs. Only approved display fields are returned.
- All admins are trusted site-wide. A compromised admin/service key/database owner can read answers and PII. Configure MFA, disable unnecessary signup, protect deployment secrets, backups and logs.
- Old images, sessions and participant records require an operational retention policy/job. Do not log request bodies, tokens, passwords, service keys or participant payloads.
- Production npm audit reports zero advisories. Full audit has five high-severity chain entries rooted in dev-only braces 3.0.3 (GHSA-vfj7-8cjw-p6xm); the registry has no newer braces release. Do not process untrusted glob patterns with the lint toolchain. The suggested cross-major lint-config downgrade is not a compatible fix.
